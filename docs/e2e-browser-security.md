# Browser security E2E

PC-31 adds a separate Playwright suite for browser and protocol boundaries. Normal `npm test` intentionally remains the fast Node/Vitest suite; CI runs `npm run test:e2e` explicitly and fails if Chromium is absent.

## Reproduce locally

The suite requires PostgreSQL on `127.0.0.1:5432` with the `office`/`office` credentials. It only accepts this isolated URL and refuses to reset any other database:

```sh
export DATABASE_URL='postgresql://office:office@127.0.0.1:5432/office_pc31_e2e?schema=public'
npm ci
npm run test:e2e:install
npm run test:e2e
```

If the database does not exist and the configured role can create databases, the harness creates `office_pc31_e2e`. It verifies that migrations are a non-empty, unique, contiguous sequence from `0001`, runs `prisma migrate reset`, and seeds deterministic browser-only identities. No production migration is introduced.

Missing Chromium fails by default. A developer may explicitly opt out locally with `ALLOW_E2E_SKIP=true`; CI rejects that variable even when Chromium is installed. Dependency and browser installation are the only steps that need internet access; test execution uses only loopback.

## Harness boundaries

- The application is reached at `https://127.0.0.1:3443`; TLS is terminated by a loopback proxy in front of the real server.
- The OIDC issuer is `https://127.0.0.1:3444` and exposes exact discovery, JWKS, authorize, token, and recovery endpoints.
- One-day self-signed leaves and private keys are generated by OpenSSL under ignored `.e2e-tmp/`, mode `0700`, and removed in the runner's `finally` block. No key is committed.
- Chromium receives `--ignore-certificate-errors-spki-list` for only the SHA-256 SPKI of the application/provider leaf. A second HTTPS server presents an unrelated generated leaf and the suite requires Chromium to reject it. There is no broad `ignoreHTTPSErrors` setting.
- The application and Playwright Node request client trust only the expected leaf through `NODE_EXTRA_CA_CERTS`. Production HTTPS origin validation and `Secure`, `HttpOnly`, `SameSite=Lax`, `__Host-eg_session` behavior are unchanged.
- The provider signs RS256 ID tokens and validates client authentication, redirect URI, one-time authorization codes, and the S256 PKCE verifier. Controlled modes corrupt state, nonce, PKCE, response issuer, signature, audience, or token time.
- Ports are fixed, retries are zero, and the Playwright worker count is one. The harness closes all started servers in `finally` and gives the application three seconds to stop before `SIGKILL`.

## Covered contracts

The browser suite covers Authorization Code + PKCE login, callback replay without a second token exchange, session fixation replacement, session/CSRF bootstrap without Web Storage persistence, strict mutation origin/content-type/token checks with unchanged target membership, ambiguous cookie and device credentials, CSP inline-script rejection, ignored proxy headers, tenant-switch MFA reauthentication and cookie rotation, concurrent-tab and independent-session revocation, current/all logout, recovery routing, invitation fragment scrubbing and one-time acceptance, enumeration-neutral unknown-account/invitation errors, signature/audience/time validation, database no-mutation invariants, mobile navigation, heading focus, and keyboard reachability.

The mock consumes authorization codes before issuing tokens, while the application consumes callback state before exchange. Browser callback replay therefore proves that no second provider exchange occurs; directly replaying a code with the encrypted PKCE verifier is intentionally impossible outside the application boundary. Provider-global logout is outside the application contract.

## Artifact policy

Tracing, video, and screenshots are disabled because protocol URLs can carry short-lived credentials and binary captures cannot be reliably redacted. A safe reporter emits only status and escaped test titles to the console and a minimal HTML report; it never includes errors, URLs, attachments, or request data. After that final HTML is written, the runner redacts text artifacts and scans every file byte-for-byte for known canaries and credential syntax. Any trace, screenshot, video, or ZIP is deleted and fails the run. A separate always-run CI scan gates upload, and a suite canary proves the post-command pass executed. Harness and runner subprocess output is line-buffered and redacted. Generated keys, reports, and test results are ignored by Git; CI retains sanitized failure output for seven days.
