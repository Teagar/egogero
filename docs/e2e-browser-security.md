# Browser security E2E

PC-31 adds a separate Playwright suite for browser and protocol boundaries. Normal `npm test` intentionally remains the fast Node/Vitest suite; CI runs `npm run test:e2e` explicitly and fails if Chromium is absent.

## Reproduce locally

The suite requires PostgreSQL on `127.0.0.1:5432` with the `office`/`office` credentials. It only accepts this isolated URL and refuses to reset any other database:

```sh
export DATABASE_URL='postgresql://office:office@127.0.0.1:5432/office_pc31_e2e?schema=public'
npm ci
npm run test:e2e:install
npm run test:e2e
```

If the database does not exist and the configured role can create databases, the harness creates `office_pc31_e2e`. It then verifies that exactly 24 base migration directories exist, runs `prisma migrate reset`, and seeds deterministic browser-only identities. No production migration is introduced.

If Chromium is missing locally, `test:e2e` prints an explicit `E2E SKIP` reason. Under `CI`, the same condition is a hard failure. Dependency and browser installation are the only steps that need internet access; test execution uses only loopback.

## Harness boundaries

- The application is reached at `https://127.0.0.1:3443`; TLS is terminated by a loopback proxy in front of the real server.
- The OIDC issuer is `https://127.0.0.1:3444` and exposes exact discovery, JWKS, authorize, token, and recovery endpoints.
- A one-day self-signed certificate and private key are generated by OpenSSL under ignored `.e2e-tmp/`, mode `0700`, and removed during shutdown. No key is committed.
- The application subprocess trusts only that ephemeral certificate through `NODE_EXTRA_CA_CERTS`. Production HTTPS origin validation and `Secure`, `HttpOnly`, `SameSite=Lax`, `__Host-eg_session` behavior are unchanged.
- The provider signs RS256 ID tokens and validates client authentication, redirect URI, one-time authorization codes, and the S256 PKCE verifier. Controlled modes corrupt state, nonce, PKCE, or response issuer.
- Ports are fixed and the Playwright worker count is one to avoid shared-database and provider-state races. Playwright owns the supervisor lifetime and sends termination on completion.

## Covered contracts

The browser suite covers Authorization Code + PKCE login, callback replay, session fixation replacement, session/CSRF bootstrap without Web Storage persistence, strict mutation origin/content-type/token checks, ambiguous cookie and device credentials, CSP inline-script rejection, ignored proxy headers, tenant-switch MFA reauthentication and cookie rotation, concurrent-tab revocation, current logout, recovery routing, invitation fragment scrubbing and one-time acceptance, enumeration-neutral errors, mobile navigation, heading focus, and keyboard reachability.

Logout-all is exercised by the existing database/API suite rather than duplicated in the browser suite; its browser continuation shares the tenant-switch reauthentication mechanism covered here. Provider-global logout is outside the application contract.

## Artifact policy

Tracing and video are disabled because OIDC URLs and request bodies necessarily contain short-lived credentials and Playwright trace archives cannot be reliably redacted after capture. Failure screenshots are allowed only after the invitation fragment has synchronously been scrubbed or on neutral error/application pages. Text artifacts are scanned during the suite and a final reporter redacts OIDC query values, session cookies, CSRF headers, invitation tokens, PKCE verifiers, and device credentials before CI can upload them. Harness subprocess output applies the same policy. Generated keys, reports, screenshots, and test results are ignored by Git; CI retains failure output for seven days.
